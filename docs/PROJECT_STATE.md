# HEALTH — состояние проекта

**Версия документа:** 2026-10-13. **Назначение:** публичная управляющая документация без медицинских сведений и закрытых идентификаторов.

## Каноническая архитектура

- **Supabase HEALTH** — единственная действующая база: полный текст REC, структурированные и производные данные, идентификаторы, журнал операций, результаты проверок и приватная схема ограниченного Writer.
- **Google Drive HEALTH/Sources** — единственное действующее первичное хранилище оригиналов медицинских источников. Физические идентификаторы и адреса конкретных объектов хранить в приватной базе, не в этом репозитории.
- **GitHub Alexio00/HEALTH** — исходный код, документация, миграции и публичный интерфейс чтения. Этот репозиторий является **управляющим хранилищем документации**; открывать REC и Sources из него нельзя.
- **GitHub Alexio000/SHEDULLER** — приватная реализация полного резервного копирования и испытаний восстановления.
- **Отдельный приватный Google Drive BACKUP/HEALTH** — активный резервный архив базы, Auth, ролей и полного корпуса Sources.
- **Приватный Writer/Verifier** — клиентский оператор, независимый проверяющий и локальные журналы. Клиентская способность не появляется автоматически из-за подключения трёх обычных плагинов.

## Статус интеграции ChatGPT Writer

Текущий production Writer активен только для утверждённого приватного оператора. **Новый ChatGPT Project пока не имеет подключённого защищённого инструмента записи.** Подключение обычных Supabase/GitHub/Drive-коннекторов не даёт права читать GitHub Secrets, вызывать текущую локальную программу или обходить ограниченные RPC. Для рабочего перехода необходим отдельный [ChatGPT Writer gateway](WRITER_CHAT_GATEWAY_RU.md) с подтверждённым владельцем и закрытым исполнителем. До его приёма — read-only для медицинских изменений. Технические задачи: HEALTH [#34](https://github.com/Alexio00/HEALTH/issues/34), приватный SHEDULLER #36.

## Актуальная эксплуатация

Supabase активирована по отдельному решению владельца 13 октября 2026 года; ограниченный Writer был включён на точно принятом SHA кода. **Проверять фактический статус перед работой**: `public.system_state`, `health_writer.runtime_policy`, `public.operations`, принятый GitHub SHA и наличие приватного оператора. Настоящий документ не заменяет свежей проверки.

- По умолчанию **доступно чтение и подготовка предложений**. Если владелец явно попросил добавить или изменить медицинские данные, система **автоматически выбирает Writer**, без второй команды «включи запись».
- Исполнение записи возможно лишь при наличии защищённого Writer-клиента, действительного принятого SHA, корректного разграничения Writer/Verifier, конкретных авторизаций intent/candidate и свежей независимой проверки.
- Обычный Supabase SQL-коннектор не является медицинским Writer. Никогда не обходить запреты прямым SQL, административным подключением или GitHub Actions с произвольными SQL/параметрами.
- GitHub Actions Secrets не раскрываются плагину GitHub или ChatGPT. Секреты доступны лишь допустимому job-контексту Actions; приватный клиент Writer получает ограниченные настройки по отдельной процедуре, без передачи ключей в чат или публичный Git.
- Writer одиночный; незавершённые операции проверяются в `public.operations`. Полные резервные копии используют согласованный барьер записи.
- После восстановления из архива Writer должен оставаться выключенным, пока не завершено отдельное принятие.

## Историческое наследие

Старая папка `HEALTH DB` на основном Drive (Registry, Records, управляющие Google Docs), старый GitHub `HEALTH_DB_old` и прежние архивы **выведены из текущего пути чтения/записи**. Они не являются источниками актуального Project State, распределителем NNN и целью записи. Они остаются **неизменёнными доказательствами миграции**, пока владелец не примет отдельное решение о сохранности или удалении.

**После принятия этого документа в main** управляющими являются `docs/PROJECT_MANUAL.md` и данный `docs/PROJECT_STATE.md`. Вся действующая документация должна ссылаться на эти пути, а не на прежнюю папку Drive. До принятия коммита действующими остаются ранее принятые правила, нельзя самовольно переключать корень проекта.

## Резервное копирование документации

Ежедневный полный медицинский архив подтверждён отдельно от данного репозитория: он **не доказывает резервное копирование GitHub-документации**. История GitHub не является независимой копией. Перед удалением старой папки проверить отдельный экспорт/архив кода и управляющих документов на резервном Drive и успешное независимое чтение/восстановление. Пока такого свидетельства нет, статус резервирования документации — **НЕ ПОДТВЕРЖДЕНО**.
