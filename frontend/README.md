# Пользовательский интерфейс HEALTH

Статическое PWA, размещённое через GitHub Pages, предназначено исключительно для **чтения** медицинских данных после авторизации владельца в Supabase. Исходные медицинские строки никогда не сохраняются в публичных файлах интерфейса.

## Навигация
На телефоне меню по умолчанию свёрнуто и открывается кнопкой «гамбургер». На компьютере меню находится в верхней части экрана и переносится по ширине. Открывается выбранная страница, а не только меню.

Разделы: Текущее состояние, Хронические состояния, Открытые случаи, Принимаемые препараты, Мониторинг, Подготовка к визиту, Будущий план, Закрытые случаи, Записи, Вакцинация. Последний раздел остаётся пустым до данных владельца. «Текущее состояние» объединяет текущие сведения без копирования медицинских сущностей.

«Подготовка к визиту» объединяет из `plan_items` явно отмеченные консультации и открытые вопросы к специалистам из `questions`. Специалисты определяются лишь по точной формулировке основания, обычно по префиксу до двоеточия. Один вопрос может относиться к нескольким явно названным врачам. Если вопрос есть, а запланированного визита нет, новый приём не выдумывается. Внутренние вопросы карты с `metadata.category=medical_card` или `metadata.purpose=medical_card` остаются в текущем состоянии.

## Доступ и приватность
- Браузер имеет права SELECT, не INSERT/UPDATE/DELETE.
- Анонимные пользователи не могут читать медицинские таблицы.
- Реальные медицинские данные не встроены в GitHub Pages или JavaScript.
- Физические Google Drive object ID получаются только после авторизации к закрытой базе.
- Запись выполняется не через PWA, а отдельным ограниченным Writer по явной команде владельца.

## Таблицы: сортировка и фильтры
В каждой таблице сортировка вызывается щелчком по заголовку; направление чередуется, дополнительной строки текстовых фильтров под заголовками нет. Заголовки центрируются по горизонтали и вертикали. Допустим перенос по границе слов, но не посимвольное разбиение длинных слов. Предпочтительна горизонтальная прокрутка. Вертикальные отступы — половина высоты строки сверху и снизу, независимо от количества строк заголовка. Слово «Количество» в видимой колонке сокращается до `К-во` без изменения доступной подписи или данных.

Компактные фильтры размещаются перед таблицей, только если полезны: даты, повторяющиеся категории и состояния. Раздел «Записи» имеет диапазон дат, теги, при наличии нескольких значений — тип записи и степень подтверждения. «Будущий план» — повторяющиеся типы и статусы. Для «Закрытых случаев» фильтры не нужны. По умолчанию фильтры пусты/«Все». Теги REC являются интерактивными фильтрами: щелчок переносит в список записей с выбранным тегом.

## Прокрутка и закреплённые элементы
Заголовок каждой страницы закреплён под шапкой сайта. На страницах с одной таблицей фильтры закреплены между заголовком страницы и таблицей. Заголовки таблиц остаются на экране при вертикальной прокрутке. Поскольку CSS sticky внутри горизонтально прокручиваемого контейнера работает не как закрепление к экрану, применяется синхронизированная копия заголовка, которая появляется только в пределах соответствующей таблицы. Горизонтальная прокрутка и кнопки сортировки синхронизируются. Размеры шапки измеряются динамически с учётом мобильного меню. Всё это влияет только на отображение, не на исходные строки.

## Представление REC
Интерфейс скрывает устаревшие YAML/frontmatter и технические BEGIN/END FILE/REC-обёртки, если они присутствуют в историческом `body_text`. Повторяющийся H1 используется как заголовок страницы и не дублируется внутри текста. Для внутренних заголовков сохраняются читаемые отступы. Технические хеши и роли Source не показываются по умолчанию; ссылки открывают зарегистрированный PRIMARY оригинал Drive после авторизации, номера страниц остаются видимыми. **Оригинальный `body_text` в базе не переписывается и не очищается ради интерфейса.**
