# Политика подключений Writer через Session pooler

Принято владельцем 12 октября 2026 года. Writer и резервирование используют ограниченные роли через Session pooler на порту 5432, `sslmode=verify-full`, проверенный CA и временный закрытый файл пароля с режимом 0600. Секрет с сертификатом называется `HEALTH_SUPABASE_CA_PEM`. Отсутствие/подмена CA должны блокировать соединение. Учётная запись владельца базы, `service_role` и административные пароли **не должны** попадать к Writer.

Синтетические TEST-проверки подтвердили реальную проверку сертификата TLS на клиентском соединении для тестовой роли. Это не доказательство допуска новой медицинской записи. Ограниченные `prepare`/`publish` используют тот же транспорт, а не сочетание `PGPASSWORD` и `sslmode=require`.

Для read-only диагностики явно выполнять `BEGIN READ ONLY`; одного параметра запуска pooler недостаточно для доказательства состояния транзакции. TLS клиент→pooler и pooler→PostgreSQL проверяются отдельно, нельзя без доказательства считать второе защищённым.

Принятый транспорт не заменяет подписанную авторизацию, независимую медицинскую/Source-проверку, принятие схемы Writer и полное испытание восстановления. [Оператор](WRITER_OPERATOR.md) · [Безопасность](SECURITY.md).
